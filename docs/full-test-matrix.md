# BiteSmart 全量功能测试矩阵

使用方式：每次完整验收复制本矩阵，逐项记录“通过/失败/跳过原因/证据”。自动化能覆盖的项先跑脚本，真实交互能力再人工验收。

## 1. 后端基础与通用能力

| 模块 | 功能点 | 测试方式 | 重点断言 |
|---|---|---|---|
| 启动 | 应用启动 | 自动 + 手工 | 8080 启动成功；Swagger/OpenAPI 可访问；无启动异常 |
| 配置 | MySQL/Redis/JWT/文件上传/AI/支付配置 | 手工 | 环境变量优先生效；本地密钥不提交；错误配置有明确日志 |
| 统一响应 | ResultVO/PageResultVO | 自动 | code/message/data/timestamp 结构一致；分页字段一致 |
| 认证 | 注册、登录、登出、刷新/凭证修改 | 自动 + 手工 | token 正确签发；错误密码失败；禁用账号失败 |
| 权限 | USER/MERCHANT/DELIVERY_DRIVER/ADMIN | 自动 + 手工 | 未登录 401；跨角色 403；跨商家数据隔离 |
| 文件 | 上传、下载、静态访问、类型限制 | 手工 | 超大小失败；非法类型失败；图片可预览 |
| 日志 | 操作日志、异常日志 | 手工 | 关键操作可追踪；日志不泄露密码/token/私钥 |

## 8. 端到端闭环用例

| 用例 | 角色链路 | 必须验证 |
|---|---|---|
| 用户完整下单闭环 | 用户 -> 商家 -> 骑手 -> 用户 | 加购、下单、支付、接单、备餐、出餐、骑手接单、取餐、位置上传、送达、评价 |
| 商家打烊拦截 | 商家 -> 用户 | 打烊后用户不能下单；恢复营业后可下单 |
| 退款/投诉闭环 | 用户 -> 管理员 | 用户发起，管理员处理，状态回显 |
| AI 计划闭环 | 用户 | 健康档案、生成计划、开始、打卡、换菜、同步饮食记录 |
| 权限隔离 | 四种角色 | 各角色只能进入自己的页面和接口；跨角色请求被拒绝 |
| 支付宝沙箱闭环 | 用户 -> 支付宝 -> 后端回调 | 发起支付、支付页面、returnUrl、notifyUrl、订单支付状态、重复通知幂等 |

## 9. 回归策略

| 改动类型 | 必跑范围 |
|---|---|
| 后端 service/controller/mapper | Maven test + 相关 API 冒烟 + 对应页面 |
| PC 前端页面/API 类型 | PC type-check + Vite build + 对应页面 |
| 小程序页面/API 类型 | 小程序静态检查 + 开发者工具预览 + 对应真机能力 |
| 订单/支付/库存/结算 | 自动测试 + 完整下单闭环 + 金额/库存/流水核对 |
| 配送/定位 | 骑手 API 冒烟 + 真机定位 + 用户侧轨迹 |
| 权限/登录 | 四角色登录 + 越权接口 + 页面守卫 |
