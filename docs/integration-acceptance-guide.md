# BiteSmart 联调与非功能专项验收指南

本文档用于补齐自动化测试无法完全覆盖的场景，尤其是微信小程序真机能力、支付宝沙箱、实时定位、权限隔离和异常恢复。

## 1. 验收证据

每次完整验收建议保留：

- 自动测试报告：`outputs/test-runs/<时间戳>/report.md`
- PC 端关键页面截图：登录、三类角色首页、订单详情、配送追踪、统计页
- 小程序关键页面截图：用户首页、订单详情、骑手任务、配送轨迹、商家订单
- 支付证据：支付发起参数、支付宝沙箱页面、returnUrl 回跳、notifyUrl 回调日志、订单状态
- 定位证据：骑手端上传坐标、用户端轨迹线、后端 tracking 响应
- 缺陷记录：缺陷编号、模块、复现步骤、期望、实际、优先级、修复版本

## 2. 支付专项

### 2.1 模拟支付

| 步骤 | 操作 | 期望 |
|---|---|---|
| 1 | 用户加购菜品或套餐 | 购物车金额正确 |
| 2 | 提交订单 | 生成待支付订单 |
| 3 | 使用模拟微信支付或 mock 支付 | 接口返回成功 |
| 4 | 查看订单 | 状态变为待接单/已支付；支付日志存在 |
| 5 | 重复支付同一订单 | 不应重复扣款或生成异常状态 |

### 2.2 支付宝沙箱

| 步骤 | 操作 | 期望 |
|---|---|---|
| 1 | 设置 `ALIPAY_ENABLED=true` 和沙箱密钥 | 后端启动不报支付配置错误 |
| 2 | 设置可公网访问的 `ALIPAY_NOTIFY_URL` | 支付宝能访问回调地址 |
| 3 | 用户选择支付宝支付 | 返回可打开的支付页面/表单 |
| 4 | 沙箱完成支付 | 浏览器回跳到 `ALIPAY_RETURN_URL` |
| 5 | 查看后端日志 | 收到异步通知，验签通过 |
| 6 | 查看订单 | 订单支付状态正确，支付流水金额一致 |
| 7 | 重放 notify 通知 | 结果幂等，不重复变更金额/流水 |
| 8 | 伪造错误签名通知 | 后端拒绝处理 |

注意：`application-local.yml` 只能作为个人本地配置使用，真实密钥不要提交。交付前建议把所有密钥改由环境变量注入。

## 3. 实时定位专项

### 3.1 API 冒烟

运行：

```powershell
.\tools\run_full_test_workflow.ps1 -RunApiSmoke
```

其中骑手冒烟会覆盖：

- 用户下单
- 商家接单/备餐/出餐
- 骑手注册
- 骑手接单/拒单回池
- 骑手取餐
- 骑手上传两次位置
- 用户端 tracking 查询轨迹

### 3.2 真机验收

| 步骤 | 角色 | 操作 | 期望 |
|---|---|---|---|
| 1 | 用户 | 下单并完成支付 | 订单进入商家待接单 |
| 2 | 商家 | 接单、备餐、出餐 | 生成配送任务 |
| 3 | 骑手 | 真机登录，授权定位 | 能看到待接单任务 |
| 4 | 骑手 | 接单并确认取餐 | 任务进入配送中 |
| 5 | 骑手 | 保持页面打开并移动/模拟位置 | 后端收到位置点 |
| 6 | 用户 | 打开配送追踪 | 地图显示骑手当前位置和轨迹 |
| 7 | 骑手 | 确认送达 | 用户订单变为已完成 |
| 8 | 用户 | 评价配送服务 | 骑手端可看到评价/评分 |

必须额外测：

- 用户拒绝定位授权时页面提示是否清楚。
- 骑手关闭定位权限后上传失败是否可恢复。
- 弱网下重复上传是否不会产生错乱轨迹。
- 坐标顺序是否按时间排序。

## 4. 小程序真机专项

| 能力 | 开发者工具 | 真机 | 说明 |
|---|---:|---:|---|
| 账号密码登录 | 必测 | 必测 | 开发者工具可覆盖基本接口 |
| 微信登录 | 可测 | 必测 | 依赖真实 appId/appSecret |
| 地图定位 | 可测 | 必测 | 真机权限和坐标更接近真实 |
| 支付跳转 | 部分可测 | 必测 | 沙箱/真机行为可能不同 |
| 图片上传 | 可测 | 必测 | 真机文件路径和压缩行为不同 |
| 页面布局 | 必测 | 必测 | 至少测 iPhone 宽屏和常见 Android |

## 5. 权限与越权专项

| 场景 | 期望 |
|---|---|
| 未登录访问 `/api/orders` | 401 |
| 普通用户访问 `/api/admin/users` | 403 |
| 普通用户访问 `/api/merchant/orders` | 403 |
| 商家访问其他商家的订单详情 | 失败或空结果 |
| 骑手操作不属于自己的任务 | 失败 |
| 普通用户修改其他用户地址/健康记录 | 失败 |
| 已冻结账号登录 | 失败 |
| 过期/伪造 token | 401 |

## 6. 数据一致性专项

| 链路 | 核对点 |
|---|---|
| 购物车 -> 下单 | 勾选项、数量、单价、总价一致 |
| 下单 -> 支付 | 订单金额和支付流水金额一致 |
| 支付 -> 商家接单 | 支付成功后才允许接单 |
| 商家出餐 -> 配送任务 | orderId、merchantId、地址、备注快照一致 |
| 骑手送达 -> 订单完成 | 订单状态、配送任务状态、状态日志一致 |
| 套餐换菜 | 套餐价格和营养重新计算 |
| AI 计划打卡 | 计划餐同步到饮食记录，取消打卡后删除同步记录 |
| 会员购买 | 会员状态、有效期、计划权益一致 |
| 退款/结算 | 订单、退款申请、资金流水、商家账户一致 |

## 7. 性能与稳定性专项

| 项目 | 建议标准 |
|---|---|
| 登录/详情接口 | 本地环境一般低于 1 秒 |
| 列表接口 | 必须分页；大数据量下不卡死 |
| 统计接口 | 查询期间页面有 loading；慢查询有日志 |
| 前端构建 | 生产构建通过；大 chunk 有记录 |
| 小程序首屏 | 图片压缩合理；首屏无长时间白屏 |
| 并发下单 | 库存不能扣成负数；订单金额不漂移 |
| 重复点击 | 下单、支付、接单、送达等关键按钮应防重复 |

## 8. 安全与隐私专项

| 项目 | 验收标准 |
|---|---|
| 密码 | 数据库存 BCrypt；接口响应不返回 password |
| token | 不写入日志；过期后强制重新登录 |
| 私钥 | 支付宝/微信/AI key 不进入 Git |
| 文件上传 | 限制大小和类型；上传后访问路径安全 |
| SQL 注入 | 搜索、筛选、排序参数不能拼接裸 SQL |
| XSS | 用户昵称、评论、投诉内容展示时不能执行脚本 |
| CORS | 本地开发允许；生产环境需限制来源 |

## 9. 回归出口

完整联调可以结束的条件：

- `tools/run_full_test_workflow.ps1` 基础检查全绿。
- `tools/run_full_test_workflow.ps1 -RunApiSmoke` 在本地后端、MySQL、Redis 就绪时通过。
- PC 三角色核心路径完成。
- 小程序三角色核心路径完成。
- 支付宝沙箱闭环至少完成一次。
- 真机定位闭环至少完成一次。
- P0/P1 缺陷清零，P2 有明确记录和处理计划。
